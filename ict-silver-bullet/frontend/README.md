# Vite dashboard

React + TypeScript presents the version 1 Python API. TanStack Query polls one
shared server snapshot every ten seconds. Plotly's finance bundle is loaded only
when charts are needed (about 417 kB compressed); risk meters use accessible HTML.
All assets are local. Production runs only `python -m brain.dashboard` on the
existing host/port, serving `frontend/dist`; Node is a build dependency.

From the app directory, with Brain's Python environment active:

```powershell
python -m pip install -r brain/requirements.txt
python -m brain.dashboard_dev
```

In another terminal:

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run dev
```

Open `http://127.0.0.1:5173`. Vite proxies `/api` to loopback port 7860 while
preserving Host/Origin. Set process environment `ICT_API_PORT` before starting
Vite if using another backend port. Authentication still uses the configured
dashboard username/password. No `.env` or credentials are generated by tooling.
Dev serves only on loopback; it is not the EC2 production task.

Checks and production build:

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npm.cmd run build
npx.cmd playwright install chromium
npm.cmd run test:browser
```

Browser checks launch a loopback Python fixture and use only mock data. Python,
FastAPI, Uvicorn, dotenv, tzdata and Pydantic must be available to that terminal.
They verify real compiled assets, auth, CSP, charts, desktop/mobile layout,
partial failure, growing source ages and session expiry. No live service is called.

Types are generated from the Pydantic serialization schema. When changing a
contract, from the app directory run `python -m scripts.export_dashboard_schema`,
then from frontend run `npm.cmd run types:generate`. Commit schema and types.
The Python contract test detects drift. Defaults are required in the serialized
response, which makes absent fields a version-contract failure.

`build.json` records index hash, source hash and UTC build time. Windows deployment
uses `build_frontend.ps1` to install from the lockfile, stage, validate and promote
assets. See [EC2 upgrade and recovery](../deploy/windows/README-deploy.md).

Implementation judgments (`# NOTE:` in source): sessions are in-memory, bounded
to 1024 and valid for eight hours with one worker; restarts invalidate them.
Limit baselines are recovered from persisted equity/drawdown, with missing values
left unavailable. History is bounded and chart sampling retains equity/limit
extrema and drawdown peaks. Failed reads preserve last-good panels. Old hashed assets are retained
for open tabs. Floating P/L and detector evidence require future data-source
fields and are labeled unavailable rather than inferred from realized results.
